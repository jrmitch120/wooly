Using Wooly

Everything you need to read, post and script Mastodon from your terminal. Press ? on any screen of the TUI, or add --help to any CLI command, to see the same thing in the app.

What Wooly is

Wooly is a Mastodon client for your terminal. It comes as two programs:

  • wooly-tui, a full-screen app you drive from the keyboard (or the mouse), for reading and posting.
  • wooly-cli, a command line for quick posts and for scripts, with JSON output and exit codes you can rely on.

They share one set of profiles and one config file. Sign in with either and the other is signed in too.

Install

Download what you want from the latest release. Each program is a single self-contained file, so you don't need .NET installed.

PlatformTUICLI
Linux x64wooly-tui-linux-x64.tar.gzwooly-cli-linux-x64.tar.gz
macOS Apple siliconwooly-tui-macos-arm64.tar.gzwooly-cli-macos-arm64.tar.gz
macOS Intelwooly-tui-macos-x64.tar.gzwooly-cli-macos-x64.tar.gz
Windows x64wooly-tui-windows-x64.exewooly-cli-windows-x64.exe

On Linux and macOS, unpack the tarball and run the program inside it. Moving it somewhere on your PATH, such as ~/.local/bin, lets you run it from anywhere.

tar -xzf wooly-tui-linux-x64.tar.gz
./wooly-tui

On Windows, run the .exe from Windows Terminal or PowerShell.

Check which version you have with wooly-cli version. To upgrade, download the new release and replace the old file. Your profiles and settings stay where they are. Anything you need to know when moving between releases is in the upgrade notes.

Signing in

Wooly signs in through your browser, on your instance's own page. It never asks for your password. Each account you sign in with is saved as a profile with a name you choose, such as personal or work, and you can have as many as you like, on one instance or several.

In the TUI

Run wooly-tui. The first time, it opens on Add a profile:

  1. Type your instance, for example mastodon.social, and press ⏎.
  2. Approve Wooly in the browser window that opens.
  3. Give the profile a name. You land on your home timeline.

If the browser doesn't open, or you'd rather use an access token you already have, press t at that step to paste one instead.

From the CLI

wooly-cli profile add work --instance mastodon.social

This opens your browser, then checks the sign-in with your instance before saving the profile. On a machine with no browser, Wooly prints the address so you can finish signing in on another device. If you already have an access token, pass it with --token <TOKEN>, or use --manual to be asked to paste one.

More than one profile

The first profile you add is the default, the one both programs use unless you say otherwise.

  • For one run, pass --profile <NAME> to either program.
  • To change the default, run wooly-cli profile switch <NAME>, or press D on the profile in the TUI.
  • In the TUI, ctrl-p opens Profiles. There, ⏎ switches to a profile for this session, a adds one, R signs one in again, and x removes one.
  • wooly-cli profile list and profile show tell you what you have.

Getting around

The TUI has three parts:

  • The rail on the left lists where you can go, in groups: Timelines (Home, Local, Federated), Hashtags (your own tag sets, if you have any), Explore (Discover, Search), Inbox (Notifications, Direct messages, Follow requests) and You. Unread counts sit beside the places that have them. At the foot, a gauge shows how much of your instance's request allowance is left.
  • The content panel on the right shows one screen at a time. Its title is a breadcrumb, such as Home › Post by @maria, so you always know where you are.
  • The status row along the bottom lists the keys for the screen you're on.

Opening something goes one level deeper, and esc always brings you back one level. It never quits; ctrl-q does that. The keys that work everywhere:

tab shift-tabMove down or up the rail
` ~Jump to the next or previous rail group
escBack one level
/Search
ctrl-pProfiles
\Hide or show the rail
- +Make the whole app narrower or wider
?Every key for this screen
ctrl-qQuit

The mouse works too: click the rail, a post or a link, and scroll with the wheel. Wooly remembers a hidden rail and the width you chose for next time.

Reading

Pick a timeline on the rail and move through it with j and k. Wooly loads more as you near the bottom and tells you when there's nothing older to read.

j kNext / previous post
↓ ↑ PgDn PgUpScroll without moving the selection, to read a long post to its end
⏎Open the post, with what it replies to above and its replies below
aOpen the author's profile
b fBoost / favorite, and again to undo
wWho favorited or boosted it
xShow what a content warning or a sensitive picture is hiding
← →Step through the hashtags, mentions, links and pictures in the post; ⏎ opens the one picked
1–9, 0, then vPick poll options, then vote
gRefresh

Pictures and video

On a terminal that can draw pictures (one that speaks sixel or the Kitty graphics protocol, such as Ghostty, kitty, WezTerm or Windows Terminal) they're drawn right in the post. Step to one with → and press ⏎ to see it full size, with its description underneath. Everywhere else, each picture is shown as a link with its description. Video and audio open in your own player.

Tag sets

A tag set is a name for up to twelve hashtags, followed on the rail as one timeline of the posts that carry any of them. You write them in your config file, and each gets its own place in the rail's Hashtags group:

[[tag_sets]]
name = "dotnet"
tags = ["dotnet", "csharp", "fsharp"]

Posting

Press c to write a new post, r to reply to the one you're on, or e to edit one of your own. Compose opens on its own screen. ctrl-s sends it, and esc throws it away, asking first if you've typed anything.

Above the post are a few fields. Move between them with ↑ and ↓, the way you would in a mail client:

  • To sets who can see it: public, unlisted, followers or direct. Choose with ← →.
  • Lang sets the post's language. Start typing a code or a name to pick one.
  • The content warning is what readers see before they choose to open the post. ctrl-w jumps between it and the post.
  • Media lists what's attached. ctrl-o opens a file browser (type to filter, space to pick several), and ctrl-v or alt-v attaches a picture or files you've copied. On an attachment, ⏎ lets you write its description (alt text), s marks it sensitive, and del takes it off.

Typing @ and part of a name opens a list of people to mention; pick one with ↑ ↓ and tab. On your own posts, p pins or unpins and d deletes after asking.

From the CLI:

# A post with a content warning and a described picture
wooly-cli post create "Look who turned up" --cw "cat pics" \
  --media "cat.png:a ginger cat asleep on a keyboard"

# A poll that stays open for two days
wooly-cli post create "Tabs or spaces?" --poll tabs --poll spaces --poll-open 2d

# Followers only
wooly-cli post create "Home safe" --visibility followers

Notifications and messages

The rail's Inbox group keeps its unread counts up to date as things happen, and rings the terminal bell when one goes up. (Turn the bell off with bell = false; see Settings.)

  • Notifications are grouped the way your instance groups them, so ten favorites on one post are one row. w shows who did it, d dismisses a group and D clears them all.
  • Direct messages are listed as conversations. ⏎ opens one and m marks it read. Every message in a conversation is a post, so r, f and the rest work there too.
  • Follow requests, for a locked account: a accepts and x rejects.
wooly-cli notification list
wooly-cli dm send alice@example.social "Are we still on for Thursday?"
wooly-cli account requests list

People and search

Press / and type a word, a #hashtag or an @name to search accounts, hashtags and posts at once. [ and ] move between the kinds of result. Typing a full handle or the web address of a post or profile takes you straight there.

On someone's profile:

F M BFollow, mute or block them, and again to undo
sSwitch between their posts and their posts with replies
wWho they follow and who follows them

Discover, under Explore, suggests people to follow: F follows, d dismisses. On your own profile (You on the rail), E edits your display name, bio, avatar, header and profile fields.

The CLI

wooly-cli --help lists every command, and wooly-cli <command> --help shows its options.

CommandWhat it does
profileadd, list, show, switch and remove your profiles
timelineRead home, local, federated, a tag, an account's posts or its pinned ones
postcreate, reply, edit, delete, show, boost, favorite, pin and vote, the undo of each, and favorited-by / boosted-by
accountshow, edit your profile, follow, block, mute (and undo), list followers and following, and answer requests
notificationlist, dismiss one, or clear them all
dmlist conversations, show one, send a message, mark one read
searchAccounts, hashtags and posts, or one kind with --type
versionPrint the version

Posts and accounts are named the way the commands print them: a post by the id a timeline shows, and an account as user@instance, or just user for someone on your own instance.

# Your 40 newest home posts, as JSON
wooly-cli timeline home --limit 40 --json

# Reply to a post
wooly-cli post reply 113452907716812345 "Agreed!"

# Search for a hashtag
wooly-cli search "#dotnet"

In scripts

  • Lists fetch 20 items by default. --limit asks for more, and Wooly pages through your instance for you.
  • --json works on lists, searches, posts and accounts, and on what you publish. A list comes wrapped in an object that says whether it's complete: a list cut short (by a rate limit, say) still prints what it got, with "complete": false.
  • Results go to stdout and errors to stderr.
  • Commands that ask before acting, such as post delete and post vote, take --yes to skip the question.

Exit codes keep their meaning from release to release:

0Success
1Something else went wrong
2The command was typed wrong, or used an option Wooly doesn't have
3Sign-in problem: sign the profile in again
4Couldn't reach the instance
5Rate limited by the instance; try again later

Settings

Wooly keeps its settings in config.toml, in a folder of its own:

Linux~/.config/wooly/
macOS~/Library/Application Support/wooly/
Windows%APPDATA%\wooly\

The file is meant to be edited by hand. The settings you're most likely to want:

theme = "dark"                # "dark", "light", or one of your own below

[preferences]
default_visibility = "public" # public, unlisted, followers or direct
default_language = "en"
bell = true                   # ring when an Inbox count goes up
hide_drawn_caption = false    # hide a picture's caption once it's drawn
shell_width = 100             # 50 to 100, a percentage of the terminal
hidden_rail = false
scrollbar = "block"           # block, line, left-half, right-half or none

[[tag_sets]]
name = "dotnet"
tags = ["dotnet", "csharp", "fsharp"]

# A theme only needs the colours it changes
[themes.midnight]
body = "#d5d2e0"
link = "#8fa8ff"

A colour is a hex value like #8fa8ff or a terminal colour name like bright-blue. The full list of things a theme can colour is in the theme reference.

Your sign-in tokens are never written to this file. They go in your system's keychain: Keychain on macOS, Credential Manager on Windows, Secret Service on Linux.

Troubleshooting

Pictures show up as links, not pictures.
Your terminal can't draw pictures, or Wooly can't tell that it can. Pictures need a terminal that speaks sixel or the Kitty graphics protocol. macOS Terminal draws none, and a terminal multiplexer such as tmux may not pass them through. The link and its description are always there either way.
Pasting a picture into a post does nothing on Linux.
Wooly reads the clipboard with wl-paste on Wayland and xclip on X11. Install the one for your desktop (the wl-clipboard or xclip package).
ctrl-v pastes text instead of attaching a picture on Windows.
Windows Terminal keeps ctrl-v for its own paste. Use alt-v.
Wooly warned me my token is stored in plain text.
It couldn't find a keychain, which is common on a headless server, so it saved the token in credentials.toml beside your config instead. On macOS and Linux the keychain is reached through Git's credential manager, so check that git is on your PATH.
Wooly won't start on Linux and mentions ICU.
Install your distribution's ICU package (libicu). Desktop and server installs usually have it; minimal container images usually don't.
macOS says the app can't be opened.
The builds aren't signed or notarized. Unpacking with tar on the command line is usually enough. If not, clear the quarantine flag: xattr -d com.apple.quarantine ./wooly-tui.
Wooly refuses to start because of my config file.
The message names the setting that's wrong, such as a tag set with no name or more than twelve tags. Fix that line and start again.
My comments in config.toml disappeared.
Changing the width, hiding the rail or picking a default profile from inside the TUI saves the whole file again, and comments don't survive that.
I've been signed out, or the CLI exits with code 3.
Sign the profile in again: R on it in the TUI's Profiles screen, or add it again from the CLI.
Can I turn off colour?
Yes. Wooly respects NO_COLOR and TERM=dumb, and still marks what's selected without colour.
